A PRACTICAL LOCAL TRANSFER GUIDE

A PC file, ready on your iPhone.

Download files from a Windows computer to an iPhone using local Wi-Fi, Safari, a generated password, and verified HTTPS. No cable or cloud upload.

Before you start

Use a trusted Windows computer and iPhone Safari on the same reachable private network. The computer must remain awake. Use one folder containing only files you intend to share.

Setup and download

  1. Extract the Windows amd64 or ARM64 archive. Run Start-PC-to-iPhone-Share.cmd or pc-to-iphone-share.exe. Keep the portable app outside the folder you share.
  2. Open the local dashboard URL printed in the app console. Keep that dashboard URL private; its token authorizes local management. Use the separately displayed phone URL on your receiving device.
  3. Verify the public certificate fingerprint against the dashboard through a trusted channel. Install the local certificate using your device’s trust settings. iPhone/iPad users also enable it under Certificate Trust Settings.
  4. Open the phone URL, enter the generated password, and tap a file. The browser’s download manager shows the result. Search loaded entries or choose Load more files to browse additional pages.
  5. Stop the app when finished. Existing transfers have up to 30 seconds to finish during shutdown.

Details for this workflow

Most Windows PCs use x64; ARM PCs need the ARM64 build. Extract the ZIP first and use the included CMD launcher. The unsigned alpha may be blocked by Windows protections; inspect and build source instead if needed. Safari downloads appear in Downloads or Files and do not automatically import media into Photos or Music. Do not use your Windows account password: the app generates a separate share password.

Why this avoids a cloud-upload workflow

The app streams from your computer directly over the selected local interface. It includes no cloud relay, analytics, or account system. There is no upload or write endpoint on the receiving device’s file browser.

If the connection fails

Use the exact HTTPS address and port. Check client isolation on guest Wi-Fi, the selected interface, sleep settings, and a narrowly scoped firewall rule. If the browser rejects the certificate, complete pairing on that receiving device; trust on a computer does not automatically transfer to a phone.

What to expect from this pre-release

Portable builds target Windows, macOS, and Linux x86-64/ARM64. Windows x64 and Ubuntu 24.04 x64 under WSL 2 passed local runtime checks; macOS, other architectures, and physical Linux/Wi-Fi use still require device validation. Binaries are unsigned and unnotarized. IPv6-only networks, mobile server hosting, remote internet sharing, and phone-to-computer uploads are outside this version’s scope.

The app has no file-size cap, but free storage, browser behavior, filesystem limits, and network conditions apply. A directory scan stops at 10,000 entries. Certificate pairing and local-folder selection are security decisions you make yourself.
